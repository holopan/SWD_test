### เปรียบเทียบ JSON และ Protocol Buffer

| หัวข้อเปรียบเทียบ | JSON | Protocol Buffers (Protobuf) |
| :--- | :--- | :--- |
| Format | Text-based | Binary |
| การอ่าน | อ่านและเข้าใจง่าย | อ่านไม่ได้ ต้องใช้ไฟล์ `.proto` และการ compile ช่วย |
| ขนาดของข้อมูล | ใหญ่กว่าเพราะต้องส่งทั้ง key value | เล็กกว่าเพราะส่ง value กับ field number |
| ความเร็ว | ช้ากว่า | เร็วกว่า |
| โครงสร้างข้อมูล | ยืดหยุ่นไม่บังคับโครงสร้างตายตัว | ต้องนิยามโครงสร้างในไฟล์ `.proto` ก่อนใช้งาน |
| การนำมาใช้งาน | สามารถ Parse เป็น Object ได้ในตัวภาษาส่วนใหญ่ | จำเป็นต้องใช้ Compiler `protoc` สร้างโค้ดสำหรับแต่ละภาษา |


### ข้อดีข้อเสีย
#### JSON
**ข้อดี:**
 - **อ่านง่าย** สามารถตรวจสอบความถูกต้องได้ด้วยตาเปล่าได้เลย
 - **โครงสร้างมีความยืดหยุ่น** ทำให้เราเพิ่มลด parameter ได้ง่าย
 - **ใช้งานง่าย** เดี๋ยวนี้ทุก platform นิยมใช้เป็นอย่างมากแค่รับ text มา parse ลง Object หรือ Parameter ต่างๆได้ง่าย

**ข้อเสีย:**
 - **ขนาดใหญ่** เพราะต้องส่งเป็น key value ทำให้ในเคสที่มี Parameter เยอะๆ จะมีขนาดใหญ่และซับซ้อนมากขึ้น
 - **ส่งช้ากว่า** ด้วยความที่เป็น string ทำให้อาจจะส่งไปได้ช้าอยู่บ้าง
 - **ความถูกต้องของข้อมูล** เนื่องจากเราไม่มีการบังคับ type ของข้อมูลทำให้บางครั้งเราใส่ type ผิดโปรแกรมก็อาจจะพังได้ หรือบางครั้งเราแค่พิมพ์ key ผิด ระบบเราก็อาจจะทำงานผิดพลาดเช่นกัน


#### Protocol Buffers
**ข้อดี:**
 - **ขนาดเล็ก** เพราะเป็นมีการ define ไว้แต่แรกทำให้ตัดปัญหาการส่ง key ของ value ไปทำให้ขนาดเล็ก
 - **ความเร็ว** เนื่องจากเป็น binary จึงไม่จำเป็นต้องแปลงค่าต่างๆและเป็น low level ที่คอมพิวเตอร์สามารถเข้าใจได้อยู่แล้ว
 - **มีโครงสร้างที่ชัดเจน** เนื่องจากเรา define ไว้แต่ต้นข้อมูลที่ได้มาจึงไม่ยุ่งเหยิงมาก

**ข้อเสีย:**
 - **อ่านยาก** เราไม่สามารถอ่าน binary ออกได้ง่ายทำให้ยากต่อการ debug
 - **เพิ่มขั้นตอนการทำงาน** ก่อนใช้งานเราต้อง compile ออกมาก่อนเพื่อใช้งาน
 - **ไม่นิยมใช้ใน Browser** ถ้าอยากใช้เราอาจจำเป็นต้องใช้ lib ในการรับส่งข้อมูลจะเป็นที่นิยมในระบบภายในที่ต้องการความรวดเร็ว
